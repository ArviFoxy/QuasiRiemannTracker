# `gen_hybrid.py`: Lean step certificates for the density-split chain

PR 86 proves its density chain with 46 files `Source/HybridK15_NN.lean`, "generated by
`q83/lean/tools/gen_hybrid.py`", which was never published. `gen_hybrid.py` is our own generator. For one
transition `G(B0,L0,c0) -> G(B,L,c)` with selection constants `A`, `D` it writes a Lean file that proves
PR 83's structure `HybridGates B0 L0 c0 B L c A D` (`Source/HybridGates.lean`): every one of the 14 gates
is cleared to a polynomial ratio (`clearedX`, via `mul_eq_of_cleared` and the `g*_mul` lemmas), and the
numerator is shown positive on boxes of `v in [0, c - s0]`, `s0 = (B0-B)/(L0-L)`, by exact rational Bernstein
coefficients (`bern0`..`bern4`, `box_lower`), splitting only where needed.

**Status.** Fed with the header parameters of the 46 PR 86 files it reproduces all 46 files byte for byte
(everything after the header comment), including all 941 Bernstein boxes. All 46 regenerated steps
(scratch namespace `QRH.ArviDensityLab`) elaborate in Lean against PR 83's `HybridGates`; steps 01, 23 and 46
(installed as `Submissions.arvi_density_lab.Source.Gen_NN`) have literally the type of PR 86's
`hybridGates_HybridK15_NN` and feed `K15.density_step`. Details in "Validation results".

Everything is exact (`fractions.Fraction`); Lean is never called by the generator. Generating a step takes
about 0.03 s (the whole PR 86 chain: 0.9 s).

## Usage

```
cd research/density
python3 gen_hybrid.py --B0 99999/100000 --L0 5143/2000 --c0 1397/10000 \
                      --B 2499583/2500000 --L 5133/2000 --c 1/10 \
                      --A 606531/1000000 --D 203633/500 --floor 13/20 \
                      --namespace QRH.ArviDensityLab --module Gen_01 -o Gen_01.lean
```

The report goes to stderr: for each gate the Bernstein degrees of `n` / `d`, the number of boxes and the
certified reserve (`high_at_q` is the only gate that needs more than one box in PR 86's chain: 5 to 11),
and warnings for hypotheses of `K15.density_step` that lie outside `HybridGates` (see "Extending the chain").
Errors (a gate that is not positive, parameters outside the supported region) give exit status 1.

| option | meaning |
|---|---|
| `--B0 --L0 --c0 --B --L --c --A --D` | parent `G(B0,L0,c0)`, child `G(B,L,c)`, selection `A`, `D`; exact rationals (`99999/100000`, or decimals `0.99999`) |
| `--floor P/Q` | numeral of the density-floor gate `q_floor`, default `13/20` |
| `--namespace NS` | outer Lean namespace of the file (default `QRH.SilDensitySplit`) |
| `--module M` | inner namespace; the theorem is `NS.hybridGates_M` |
| `--gates-import MOD`, `--gates-namespace NS2` | the Lean module and namespace that define `HybridGates`, `Hybrid.*`, `UnifPos` (default: PR 83's `Submissions.sil_density_split_20261026.Source.HybridGates`, `QRH.SilDensitySplit`) |
| `-o FILE` | output (default stdout) |
| `--from-header FILE` | read `B0..D` from a header line `parent G('..','..','..') -> child G(..), selection A = .., D = ..` (PR 86 files and our own files) |
| `--steps steps.json --outdir DIR --module-pattern 'Gen_{i:02d}'` | batch: a JSON list of `{"B0":..,"L0":..,"c0":..,"B":..,"L":..,"c":..,"A":..,"D":..[,"floor":..]}`; warns if a parent is not the child of the previous step |
| `--dry-run`, `--report-json FILE` | certify and report only (fast feasibility scan), machine-readable report |
| `--title TEXT` | descriptor in the header comment (`{i}` = step number with `--steps`) |
| `--gate-lib FILE.py`, `--list-gates`, `--extra NAME=VAL` | other gate sets, see below |
| `--check-gates-file HybridGates.lean` | first check the gate library against that Lean source |
| `--max-heartbeats N` | `set_option maxHeartbeats` in the file (default `1000000`, PR 86's value) |
| `--marked` | certify `HybridGatesM` (marked HIGH gate, this package): see "Marked HIGH gate" below; defaults `--gates-import Submissions.arvi_density.Source.HybridGatesMarked`, `--gates-namespace QRH.ArviDensity` |
| `--marked-max-boxes N`, `--marked-force-split 0,2` | box limit per branch (default 400); axes (0 = v, 1 = t, 2 = p) bisected unconditionally first (tests the cover code) |

Python API: `res = gen_step(B0, L0, c0, B, L, c, A, D, floor, namespace, module)` (Fractions, ints or strings
like `'99999/100000'`), or `generate(Params(..., floor=Fraction(13, 20)), namespace=..., module=..., lib=PR83_LIB)`.
`res.text` is the Lean file, `res.report` / `res.summary()` the report, `res.warnings` the list of warnings,
`res.certs` the exact data (polynomials, boxes, Bernstein coefficients).

The generated file imports only the gates module. If `--namespace` differs from `--gates-namespace` it
issues `open <gates namespace>`, so a file in `QRH.ArviDensityLab` uses PR 83's `QRH.SilDensitySplit.*`
unchanged. The header comment is our own (it carries a `parent G(..) -> child G(..), selection ..` line, so
`--from-header` also reads our files); PR 86's header (copyright line, "generated by q83/...") is not
reproduced.

## What a generated file contains (PR 86's layout)

1. `import <gates module>`, `set_option autoImplicit false`, `set_option maxHeartbeats 1000000`, namespaces,
   `open Hybrid`.
2. `cross_eq` (`cross B0 L0 B L = s0`), `x_pos` (`0 < 1 + D v`), `E_pos` (`0 < densE ..`),
   `F_pos` (`0 < 15 densE - 6 densK`).
3. For each gate, in the order of the structure: `nX`, `dX` (integer polynomials), `clearedX`
   (`gX .. v * dX v = nX v` from `gX_mul` by `mul_eq_of_cleared` and a `ring` identity),
   for each box `k`: `nX_bern<k>`, `dX_bern<k>` (the polynomials on `lo + (hi-lo) t` equal `bern<deg>` of the
   exact Bernstein coefficients), `boxX_<k>` (via `box_lower` and `bern<deg>_ge/_le`), then the chain
   `uptoX_<k>` (glued by `lower_of_two_boxes`) and `unifX : UnifPos (gX ..) 0 (c - cross ..)`.
4. `theorem hybridGates_<module> : HybridGates B0 L0 c0 B L c A D` with the six non-interval fields as in
   PR 86 and the 14 gate fields `q_lower := <module>.unifQLower`, ...

No `sorry`, `admit`, `axiom`, `native_decide` (the generator refuses to emit them); the theorems depend on
`propext`, `Classical.choice`, `Quot.sound` only.

## Certification rules (reverse-engineered from the 46 files; each is verified exactly)

* **Cleared pair.** Each gate has a cleared pair `(Ng, Dg)` of exact polynomials in `v`, transcribed from its
  `g*_mul` lemma (`g * Dg = Ng`). `n, d` are the *primitive integer* polynomials proportional to it:
  multiply by the lcm of all coefficient denominators, then divide by the gcd of all integer coefficients of
  `n` and `d` together. The data fix this normalisation: the gcd is 1 for 583 of the 644 (step, gate) pairs
  of PR 86, but 3, 27 or 4107 for all 46 `high_at_q` pairs and 3 or 37 for `q_lower`, `q_upper`, `q_floor` in
  steps 18-37.
* **Bernstein degree** = exact degree of the polynomial, separately for `n` and `d` (e.g. `retained_cap`:
  `bern2` for `n`, `bern1` for `d`; `low_per_excess_width`: `bern0` / `bern1`).
* **Boxes.** Start with `[0, c - s0]`. A box is accepted if all Bernstein coefficients of `n` and of `d` on it
  are `> 0`; otherwise it is bisected at the midpoint and both halves are treated the same way (left to
  right). For `high_at_q` (whose numerator dips close to zero near the left end) this gives, in 41 of the 46
  PR 86 steps, `[0, h/2^(K-1)], [h/2^(K-1), h/2^(K-2)], .., [h/2, h]` with K = 5..8; in steps 16-19 the box
  `[h/128, h/64]` is bisected once more (9 boxes) and in step 12 down to depth 3 (11 boxes). Every other
  gate of the 46 steps passes with one box. If a gate is not positive at some box end the generator stops
  with an error naming the gate and the point (no subdivision can help); a depth limit (60) catches
  interior zeros.
* **Per box:** `m` = smallest Bernstein coefficient of `n`, `M` = largest of `d`, reserve `m/M` (reduced).
  The gate reserve is the minimum over its boxes.
* **Self-checks before writing** (exact, Python only): `value(v) * Dg(v) = Ng(v)` for the independent
  transcription of the gate function (`Gate.value`) at 11 rational points, `Ng * d = n * Dg` identically,
  and "reserve <= gate value" at those points. Parameters for which the fixed Lean scripts for `cross_eq`,
  `x_pos`, `E_pos`, `F_pos`, `width_pos` would fail are rejected (`L0 > L`, `D >= 0`, `c > s0`,
  `densE(0) > 0`, `15 densE(0) - 6 densK > 0`).
* **Bernstein degrees above 4.** PR 83 has `bern0`..`bern4`. For a gate with a polynomial of degree 5 or more
  the generator emits local `lbernN`, `lbernN_ge`, `lbernN_le` (same proof as `bern4_ge`) in the file; tested.

## How to change the floor, or a gate

A gate in `gen_hybrid.py` is one `Gate(...)` object: the Lean names (`lean_fn`, `fn_args`, `mul_lemma`,
`mul_args`, `hyps`, `ne_expr`, `simp`), the cleared pair `cleared(P) -> (Ng, Dg)` and an independent exact
`value(P, v)` of the gate function. The generated Lean (names, `clearedX` proof, boxes, structure field) is
produced from that object, so changing a gate is changing its object. The Lean library is the other half.

### The floor numeral (`q_floor`, 13/20 today)

In Python it is `Params.floor` / `--floor`; it only enters `cleared` of `q_floor` (`Ng = K - floor*E`).
In Lean the numeral is in three places of `HybridGates.lean`: `gQFloor`, `gQFloor_mul`, `HybridGates.dens_floor`.
So a lower floor needs a copy of the library:

```
python3 make_gates_variant.py --floor 3/5 --namespace QRH.MyLab.F60 -o <lab>/HybridGatesF60.lean
python3 lean_model_check.py <lab>/HybridGatesF60.lean --floor 3/5          # no Lean needed
python3 gen_hybrid.py ... --floor 3/5 --gates-import Submissions.<lab>.Source.HybridGatesF60 \
                      --gates-namespace QRH.MyLab.F60 --namespace QRH.MyLab.Steps --module Step47 -o Step47.lean
```

Not covered: PR 83's analytic files (`Density/Price.lean`, `Leaf*.lean`, `StepGates.lean`) consume
`QRH.SilDensitySplit.HybridGates` and hard-code the clip `[13/20, 3/4]`; they must be adapted separately.
To drop the floor gate altogether use `lib.without('q_floor')` (the field disappears from the generated
structure as well).

### Replacing, adding or removing a gate (e.g. a new HIGH gate)

1. In the Lean copy of `HybridGates.lean`: define the function, prove its `_mul` lemma `g * Dg = Ng` and
   change the structure field `key : UnifPos (g args) 0 (c - cross B0 L0 B L)`.
2. In a Python file passed as `--gate-lib` (see `example_gate_lib.py`):

   ```python
   from dataclasses import replace
   def modify(lib):                       # `gh` = gen_hybrid is available in the file
       old = next(g for g in lib.gates if g.key == 'high_at_q')
       new = replace(old, lean_fn='gHighNew', mul_lemma='gHighNew_mul',
                     cleared=my_cleared,      # Params -> (Ng, Dg), exact Poly objects (Poly, V, P.X, P.E, P.F, P.W, P.K)
                     value=my_value)          # (Params, v) -> Fraction, transcription of the Lean definition
       return lib.replace('high_at_q', new)   # or lib.add(Gate(..), after='high_at_q'), lib.without(key)
   ```

   Extra scalar parameters of a new gate: `--extra K=3/4` (readable as `P.get('K')`, usable in `fn_args`).
   Extra hypotheses or positivity lemmas: `lib.with_hyp('hG', "  have hG := (G_pos v h0).ne'")` and a
   template in `lib.preamble_lemmas` (placeholders `{D}`, `{A}`, ... are Lean literals).
3. `python3 lean_model_check.py <HybridGates copy> [--floor ..]` evaluates the Lean definitions and `_mul`
   statements exactly (a small interpreter for the `+ - * / ^` fragment) and compares them with the Python
   gate: gate function vs `Gate.value`, `Ng/Dg` vs the lemma, structure fields and argument lists. A
   mismatch is reported here instead of by a failed `ring` inside Lean. `gen_hybrid.py --check-gates-file`
   runs the same check first.
4. Generate. The generated `clearedX` proof is the same for every gate:
   `mul_eq_of_cleared <Dg ≠ 0> (gX_mul .. v hyps) ?_; simp only [nX, dX, ..]; ring`.

### Extending the chain past PR 86 (lower floor)

1. Write the steps as exact rationals, each child equal to the next parent (`steps.json`, see `--steps`).
2. `python3 gen_hybrid.py --steps steps.json --dry-run --floor 3/5 --report-json rep.json` certifies every
   gate of every step in exact arithmetic (about 30 ms per step) and reports degrees, box counts and
   reserves without writing Lean. A step that is not provable stops with the gate and the point; it also
   warns when a hypothesis of `K15.density_step` outside `HybridGates` fails (`DSFace`: `B <= B0 < 1`,
   `1 < L < L0`, `c0, c < 1/6`; `0 < L0, B0, c0`).
3. Make the Lean copy of `HybridGates` for the floor (above) and write the files with `--outdir`,
   `--module-pattern`, `--gates-import`, `--gates-namespace`, `--title 'density step {i}'`.

Chain assembly (`ChainK15`-style `have sNN := density_step ..` lines) is not generated.

Test of this workflow: the 74 float steps of the scratchpad file
`$SCRATCH/analysis/B2/dch_pr83_f60.json`
(a floor-0.60 chain from the PR 86 boot face; rationalised to 1e-9 in `B`, 1e-6 in `A`, 1e-3 in `D`, `L` on the
1/2000 grid, each child made the next parent) all certify with `--floor 3/5`: 1621 boxes, `high_at_q` needs 4
to 10 boxes, no other gate more than one, smallest reserves `q_floor` 1.0e-6 and `high_at_q` 1.3e-8. With the
default floor 13/20 steps 20 to 74 fail in `q_floor` (55 of 74 steps). Steps 20 and 74, generated against
`HybridGatesF60`, compile in Lean (12.0 s and 10.6 s wall, no output); their `B` has 10-digit denominators.
This is a test of the generator on realistic inputs, not a claim about the chain itself.

## Marked HIGH gate (`--marked`): `HybridGatesM`

`Submissions.arvi_density.Source.HybridGatesMarked` defines `HybridGatesM qf B0 L0 c0 B L c A D`: the fields of the
fork's `HybridGates qf` without `high_at_q` and `high_density_derivative`, plus

```
high_marked : ∃ r > 0, ∀ v ∈ [0, c - s0], ∀ ν ∈ [q(v), 3/4],
   r ≤ highJ B L (s0 + v) (u v) ν + gainC ν B0 L0 c0 (s0 + v - u v) (1 - 6 u v)
```

(`gainC`: PR 76's repeated-mark gain, K = 8 copies; `highJ = (1-ρ)(1-6u) - ν(B-(L-1)w-u) + u`, so the unmarked
reserve is the case `gainC = 0`). The marked ledger needs exactly this (`Density.ds_ledger_marked`): the marked excess
`ν s - gainC ν … s H` is nondecreasing in the retained width `s`, so the HIGH payment is the one at `s = w - u`.

**Certification.** `gainC = inf_{p ∈ [0,1/2]} min_{k} facetVal_k`, six branches `k = (i,j)` (inverse `i ∈ {0: eight
copies of the slots, 1: inverse cap}`, plain `j ∈ {0: slots, 1: width cap, 2: affine cap}`), each facet linear in
`(S, Q)` with coefficients rational in `(ν, p)`. Hence it suffices that for every branch
`G_ij(v,ν,p) = highJ + facetVal_ij ≥ r` for `v ∈ [0,h]`, `h = c - s0`, `ν ∈ [q(v), 3/4]`, `p ∈ [0,1/2]`
(`le_gainC_of_facets`). Facts that shaped the design (numerics in `research/density`, checked on PR 86's steps):

* `G_ij` is **not monotone in `ν`** (the eight-copy inverse facets decrease in `ν` at large `p`), so the unmarked
  reduction "gate at `ν = q(v)` plus the density-derivative gate" does not apply; the gate is quantified over `ν`.
* A constant lower end `ν₀ ≤ min q(v)` for the box is lossy: `q(v)` drops by up to `0.05` over `[0,h]` in the early steps,
  while `highJ` has slope `≈ 0.4` in `ν` (PR 86 step 1: `highJ(ν₀) = -0.017` against a margin of `2·10⁻⁴`).
* So the density is the box variable `t ∈ [0,1]`, `ν = q(v) + t (3/4 - q(v)) = Y/E`, `E = densE`,
  `Y = densK (1-t) + 3/4 t E`: the region is the **box** `[0,h] × [0,1] × [0,1/2]`, without loss.

With `X = 1 + D v`, `U, αU, βU, eU` the denominator-cleared coefficients of the branch (`offS`, `offQ`, `slopeExcess` of
`Gain/Gain.lean`; e.g. branch `(1,2)`: `U = (1-p)(L0-2p)`, `αU = 0`, `βU = p(L0-2p) + B0 p (1-p)`,
`eU = p(L0-2p) + p(1-p)`) and `d̂ = (15-6ν)/2·U + (5-6ν)·eU`:

```
G_ij · X d̂ = ν (5 QX U + (5-6ν)(αU SX + βU QX)) + ν ((1-2p) SX - PiX) d̂ + (A v) d̂,
SX = w X - A v,  QX = X - 6 A v,  PiX = (B - (L-1) w) X - A v,  w = s0 + v           (Lean: gHighM_ij, cNumM, cDenM)
```

(the identity `highJ + facet = ν (root + (1-2p)S - Π) + u` uses `(1-ρ) = ν ξ₀`). Multiplied by `E²` at `ν = Y/E` it is a pair
of polynomials in `(v,t,p)` of degree `(4,2,≤3)` / `(3,1,≤2)` (`cNumY`, `E · cDenY`, `gHighM_scaled`). They are made primitive
integer polynomials (as in the one-variable gates) and certified by exact tensor Bernstein coefficients on boxes of
`[0,h] × [0,1] × [0,1/2]`: a box is accepted when all Bernstein coefficients of `n` and of `d` are positive, else it is
bisected along the variable that raises the smallest `n`-coefficient the most (a non-positive corner value is an error:
no subdivision can help). The Lean text per branch: `nM_ij`, `dM_ij`, `clearedM_ij` (`mul_eq_of_cleared`, `gHighM_scaled`,
`ring`), per leaf the nested Bernstein forms (`bern2 (bern2 (bern3 …))`, outermost `v`), `box_lower3`, the cover by
`rcases le_total`, and `markedHigh` (`exists_nuT`, `le_gainC_of_facets`, `forall_branch`). The reserve is the minimum of
`m/M` over all boxes, rounded down to 3 significant digits.

**Results.** All 46 PR 86 steps at floor `3/5` (`validate_marked.py`): one box per branch (276 boxes), global reserves
`4.5·10⁻⁵ … 2.7·10⁻³` (20 s for the 46 files with all gates); the 74 steps of the floor-0.60 chain of the scratchpad
(`dch_pr83_f60.json`, rationalised as above): one box per branch. A transition beyond the unmarked gates: PR 86's parent
of step 46 with `B` lowered by `3/10000` and `A = 2/5` (`high_at_q = -0.0045` at `v = 0`, the unmarked generator
refuses it): six boxes, reserve `41/25000`; lowering `B` by `25/100000` with `c = 9/100` makes `highJ + facet_(1,0)`
negative at `(v,t,p) = (0,0,1/2)` and the generator stops there.

**Lean.** `python3 gen_hybrid.py --from-header HybridK15_46.lean --floor 3/5 --marked --namespace QRH.ArviDensity
--module HybridMarkedK15_46 -o ...` writes `Submissions/arvi_density/Source/HybridMarkedK15_46.lean` (945 lines, elaborates
in about 40 s, no output); `MarkedStepTheorem.lean` feeds it, and `HybridMarkedStretch46`, to `Density.density_step_marked`
(`#print axioms`: `propext`, `Classical.choice`, `Quot.sound`). With `--marked-force-split 0,2` the same step is
emitted with four boxes per branch (1575 lines, 68 s) and compiles, which exercises the box-cover code.

Limits: the marked mode needs the fork's `HybridGates` conventions (`gQFloor qf …`); `--check-gates-file` is not supported with
`--marked` (the gate definitions are checked by compiling the file); the parent must satisfy `22/23 ≤ B0 ≤ 1`, `1 < L0`,
`0 ≤ c0 ≤ 1` (the range of the gain lemmas); `density_step_marked` needs `22/23 ≤ B0` and `DSFace`.

## Notes and limits

* The box/degree/normalisation rules above are inferred from the 46 files; they are exact for all of them
  but PR 86's generator could behave differently outside that data (e.g. other subdivision orders for
  gates that need several boxes; we bisect at midpoints). Whatever is generated is proved by Lean, not by
  the generator.
* The Lean scripts of `cross_eq`, `x_pos`, `E_pos`, `F_pos` are PR 86's fixed ones (`norm_num [cross]`,
  `nlinarith`, ..); they are valid for the parameter region the generator checks (see above).
* `set_option maxHeartbeats 1000000` is per declaration and was enough for all 46 steps; larger
  denominators of the parameters (more digits) or many boxes may need `--max-heartbeats`.
* Lean's module lookup takes the *first* `LEAN_PATH` entry that has a `Submissions/` directory. A scratch
  `.olean` outside `.lake/build/lib/lean/Submissions/` is therefore not found when imported by name, unless
  that directory is an overlay of the real one (what `run_lean_check.sh` builds) or the `.olean` is placed in
  `.lake/build/lib/lean/Submissions/arvi_density_lab/Source/`.
* The scratch files `Gen_01`, `Gen_23`, `Gen_46`, `Gen_Test`, `HybridGatesF60`, `Gen46F60` sit in
  `/home/user/lean-env/qrh/Submissions/arvi_density_lab/Source/`; the library glob `Submissions.+` of the
  Lake project includes them in `lake build Submissions`.
